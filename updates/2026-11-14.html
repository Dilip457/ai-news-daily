Concept of the Day

The agent gets a wallet

What changes when software can pay, and who carries the risk when it pays wrongly

For two years the agent conversation has been about capability: can the model plan, use tools, recover from a failed call. This week the conversation moved to settlement. OpenAI's ChatGPT Wallet lets a dots agent complete a purchase, and the design choices in it are more interesting than the feature. The user adds a card once. Before every purchase they see the merchant, the items, the total and the card, then approve with a biometric check. The card network then issues a payment token — a scoped card number, security code and expiry that exist for that transaction only — so neither the merchant nor the agent ever holds the real card details.

That last detail is the actual engineering. Agent security debates usually centre on prompt injection: can a malicious web page talk the model into doing something. Payments reframe it as an authorisation problem. If the agent can only spend against a token the user approved, and each approval leaves a record of what was authorised, then a hijacked agent produces a failed purchase rather than a drained account. The failure mode becomes annoying instead of catastrophic, which is the right trade for a first generation.

The commercial side is messier. OpenAI is not taking a cut at launch and is instead asking merchants to make themselves reachable: claim a business profile, configure CDNs and firewalls to recognise signed agent requests, work with risk providers so legitimate agent purchases are not declined as fraud. That is a lot of unpaid work for a retailer, and the largest ones are declining it. Amazon already blocks agent purchases and steers shoppers to its own assistant; United said it will block agents from booking tickets.

So the likely near-term shape is not one agent-friendly internet but a split one: sellers who opt in because agent traffic is revenue, and sellers who opt out because agent traffic is a margin and relationship threat. Google's move in the same direction — connecting Gemini to Google Wallet so it can answer questions about your spending — makes the split sharper, because now one assistant can both read your finances and, in time, act on them.

The unsolved part is liability, and it is unsolved because the technology moved first. If an agent buys a non-refundable ticket at the wrong price, the card protections apply to a disputed charge, not to a bad decision. OpenAI's answer is that users will eventually set spending limits, categories and time windows and pre-approve within them, which quietly converts a product feature into a personal policy engine. Until those defaults exist and are legible, 'the agent did it' is a sentence with no legal owner.

Which is why the least glamorous item of the week may matter most. Anthropic's coordination study found that a single shared agent beat teams of per-user agents by 10 to 45 points, and that team episodes carried far more unsupported claims about other people. Add durable run state, spend caps and approval gates from the open-source agent platforms, and a pattern emerges: the systems that will be trusted with money are the boring ones, with fewer moving parts, one accountable coordinator and a hard stop before the irreversible step.
