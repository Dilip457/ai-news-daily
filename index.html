Concept of the Day

Decision Models

A new class of model that returns typed, calibrated choices instead of text

A decision model does not write prose. Give it a state - a support ticket, an agent's current step, a row of data - and a set of typed questions, and it returns a probability for each allowed answer, plus a confidence value. The calling software then acts above a threshold and escalates below it.

The idea was popularised by TypeSafe AI's Jev, which returns Choice, Score and Noul answers at roughly $0.042 per million input tokens and latency of 70-500ms. Because the output space is closed, the model cannot emit an invalid type, and there is no free-form text to parse.

This week the category went mainstream. Amazon released Strands Decider 2B, Cloudflare shipped Clef and Clef-flash under Apache 2.0, and Fastino Labs introduced GLiDE, the first decision model with adaptive reasoning, which it says leads Jev on the official Decision Index.

The appeal is economic and architectural. Agents make dozens of small choices - route this, block that, escalate the other - and spending a frontier LLM call on each one is wasteful. A decision model handles the routine step cheaply and deterministically, reserving the large model for genuinely open-ended work.

There are limits worth respecting. Jev cannot emit an invalid type, but it can still emit a confidently wrong valid value, so calibration and threshold design matter. Early reviewers also warn that out-of-distribution behaviour will differ from an LLM's, and that maths and date logic are better left in code.

The likeliest outcome is not that decision models replace LLMs but that they become their own layer of the stack - much as retrieval did - sitting between an agent's planner and the tools it calls.

The dominant story today is AI safety.
